# Фиксы main по опыту clean-mvp

## Зачем

На стенде main (snmpsh.ru, `sha-b466e26`) при подготовке демо всплывает:

- ни у одного из 301 кадра нет камеры: при загрузке камеру не выбрать;
- дата ни у одного кадра не со штампа, только из имени файла или вручную; имя файла у
  выгрузок с камер — момент выгрузки, а не съёмки (49 кадров Березников «за 27.09»);
- камера со стримом ни разу не попробовала снять кадр (`STREAM__ENABLED=false`);
- итог «Отклонений нет» рядом с четырьмя критичными отклонениями (Березники);
- три критичных отклонения из одного снимка за день, под которым сам стенд пишет
  «по одному кадру вывод делать нельзя» (Москва, Пермь);
- этап одновременно «опережает на 57 дней» и с критичным отклонением;
- 45 строк графика Березников — 45 этапов, название этапа — абзац перечня работ.

В clean-mvp (`../LCT-7-clean`) эти случаи уже разобраны. Здесь — фиксы в коде main:
структура, таблицы и API main остаются, правила и экраны доводятся до поведения clean.

## Правила

1. Правим код main. Из clean берём правило, тест-сценарий и текст для пользователя.
2. Миграции — продолжение цепочки main (`0013+`), только аддитивные.
3. API обратно совместим: новые поля необязательные, новые эндпоинты — новыми путями.
4. Тест main, проверявший старое ошибочное поведение, правится вместе с поведением —
   с пояснением в описании PR.
5. Каждый PR — в `port/clean`, зелёный: `make check`, тесты бэкенда, `make front-check`,
   тесты ML по затронутому. В `main` — один PR после прогона демо на стенде.

## PR

| № | Тема | Что меняется |
|---|---|---|
| 1 | Камера и штамп | Выбор камеры при загрузке; чтение штампа камеры по умолчанию; у кадра камеры с непрочитанным штампом дата не из имени файла |
| 2 | Итог и отставание | «Не начат» после планового начала — отставание «от N дней»; итог по худшему этапу и согласован с отклонениями; устаревшие данные и низкая наблюдаемость — оговорки |
| 3 | Отклонения без ложных «Критично» | «Несоответствие этапу» и «Нет маркерной техники» по окну дат, «Критично» только серией; день с одним кадром не основание; без дублей по этапам; только машины в зоне |
| 4 | Маркеры этапа | Маркер — техника, отличающая этап от идущих одновременно; неразличимые этапы — пометка вместо «опережает»; позднее начало без кадров до него — не отставание |
| 5 | Время кадра | Время с часами (новая колонка), неуверенный штамп — подсказка вместо даты, OCR не ставит дату сам, проверка серии штампов камеры |
| 6 | График | Короткое название этапа без перечня работ; работы одного родителя — один этап |
| 7 | Стрим | Снимки по расписанию на стенде, пробный кадр до сохранения камеры |
| 8 | Наблюдения | Кадры по камерам, «Все дни» при малом числе кадров за последний день |
| 9 | Плавность интерфейса | Предзагрузка данных объекта, без скачков при переходах, приближение кадров последнего наблюдения, скелетоны |
| 10 | Демо и документация | Скрипты демо-объектов под API main, `documentation/` |

## Проверка в конце

Демо-объекты заливаются скриптами из PR 10, сценарий `docs/demo.md` проходится руками,
каждый пункт из «Зачем» сверяется на стенде.
