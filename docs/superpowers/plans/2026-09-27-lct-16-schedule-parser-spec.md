# LCT-16 — Парсер графика: подстрочное совпадение шапки + двухстрочная шапка

**Linear:** LCT-16 — https://linear.app/kaiangel/issue/LCT-16/parser-grafika-ne-prinimaet-realnye-shablony-xlsx-tochnoe-sovpadenie
**Связано:** LCT-7 (домен schedule, уже Done — это дефект на боевом сценарии)

## Обзор

Парсер расписания (`backend/app/domains/schedule/parser.py`) не принимает
реальные официальные шаблоны графиков СМР по двум причинам:

1. `_find_header` требует **точного** совпадения содержимого ячейки с одним
   из коротких синонимов (`NAME_HEADERS`/`START_HEADERS`/`END_HEADERS`).
   Реальные шаблоны используют длинные официальные формулировки
   («Наименование этапа выполнения контракта и (или) комплекса работ и
   (или) вида работ...»), которые не совпадают целиком ни с одним
   синонимом, хотя явно содержат нужное слово.
2. Шапка часто разбита на **две соседние строки**: в строке N — общий
   заголовок колонки (например, объединённая ячейка «Сроки исполнения
   этапа»), а фактические подзаголовки «Начало выполнения работ» /
   «Окончание выполнения работ» — в строке N+1. Текущий код ищет все три
   колонки строго в одной строке.

Также сообщение об ошибке `"Не найдена колонка с названием работы"` не
подсказывает, какие названия колонок распознаются.

Это чистый, изолированный баг-фикс внутри одного файла (`parser.py`) плюс
одна строка текста на фронтенде — без изменений схемы БД, API-контракта
или моделей.

## Архитектура и компоненты

Никаких новых компонентов. Меняется только внутренняя логика
`ScheduleParser`:

- `_find_header(row)` — совпадение по подстроке вместо точного равенства,
  через новый приватный метод `_match_header_row(row, allow_weak_name)`:
  сначала пробуются «сильные» синонимы названия (все, кроме короткого
  «этап»), и только если имя не нашлось — разрешается и «этап» (иначе он
  перехватывает служебные колонки вроде «№ этапа»/«Номер этапа»).
- Новый приватный метод `_merge_header_rows(row, next_row)` — построчное
  объединение двух соседних строк для случая двухстрочной шапки; берёт
  непустую ячейку из **второй** строки, иначе — из первой (в объединённой
  ячейке Excel заголовок-категория «оседает» в верхней строке диапазона, а
  конкретные подписи колонок — в строке под ней).
- Новый приватный метод `_row_has_date_value(row)` — определяет, похожа ли
  строка на строку данных (содержит настоящую дату), а не на шапку.
- Новый приватный метод `_locate_header(all_rows)` — единая точка поиска
  шапки (заменяет дублированный цикл в `_parse_xlsx` и `_parse_csv`):
  просматривает всё окно первых 10 непустых строк (не останавливаясь на
  первом частичном совпадении, чтобы преамбула перед шапкой не перехватила
  её раньше времени), пропускает строки, похожие на данные
  (`_row_has_date_value`), и для каждой оставшейся позиции пробует и
  текущую строку, и — если следующая строка не похожа на данные —
  объединение текущей и следующей. Из всех кандидатов побеждает самый
  полный (больше найденных колонок); при полном совпадении (все три
  колонки) поиск останавливается сразу.
- `_parse_xlsx` и `_parse_csv` используют `_locate_header` вместо
  собственного дублированного цикла.

На фронтенде — только текст подсказки в `FileDrop` на
`frontend/src/pages/NewSitePage.tsx` (сама структура компонента не
меняется).

## Интерфейсы / контракты

`ScheduleParser.parse(filename: str, content: bytes) -> ParseResult` —
публичный контракт **не меняется**: та же сигнатура, тот же `ParseResult`,
`ParsedRow`, `ParsedIssue`, `ScheduleFormatError`. Только внутреннее
поведение поиска шапки.

`_find_header(row: list | tuple) -> dict[str, int] | None` — контракт
(вход/выход) не меняется, меняется только правило совпадения внутри
(подстрока вместо точного равенства, двухпроходное: сначала без «этапа»,
затем с ним); при совпадении нескольких ячеек одной категории побеждает
**первая** найденная (детерминированное поведение, полезно для
двухстрочного случая, где могут встретиться и короткая, и длинная
формулировки).

`_merge_header_rows(row, next_row) -> list[object]` — новый приватный
метод, не публичный контракт; при непустых значениях в обеих строках
побеждает ячейка из **второй** строки (см. «Архитектура и компоненты»).

`_row_has_date_value(row) -> bool` — новый приватный метод, не публичный
контракт.

`_locate_header(all_rows) -> tuple[dict[str, int], int] | None` — новый
приватный метод: возвращает `(header, header_row_idx)`, где
`header_row_idx` — индекс в `all_rows` **последней** строки шапки (данные
начинаются со следующей записи), либо `None`, если шапка не найдена ни в
одной из первых 10 непустых строк (и как одна строка, и как объединение
пары соседних). Строка, похожая на данные, никогда не считается шапкой —
ни сама, ни как вторая строка объединения. Возвращает самый полный
кандидат из всего окна, а не первый частичный.

## Обработка ошибок

Сообщение `ScheduleFormatError` при отсутствии колонки с названием
расширяется списком распознаваемых названий, но **сохраняет префикс**
`"Не найдена колонка"` — существующие тесты матчатся по этому префикту
через `pytest.raises(ScheduleFormatError, match="Не найдена колонка")` и
не должны сломаться.

## Тестирование

`backend/tests/test_schedule_parser.py` — новые кейсы (класс
`TestScheduleParserHeaders`):

- Совпадение по подстроке: ячейка с длинной официальной формулировкой,
  содержащей «наименование» — как отдельное поле CSV.
- Двухстрочная шапка в XLSX: имя в строке 1, начало/окончание — в
  строке 2 (структура повторяет реальный файл: `№`, длинное название
  колонки, объединённая метка сроков в строке 1; фактические
  «Начало выполнения работ» / «Окончание выполнения работ» — в строке 2).
- Обновлённый текст ошибки при отсутствии колонки — по-прежнему
  match'ится по `"Не найдена колонка"`, и дополнительно содержит хотя бы
  одно распознаваемое название (например, «название»).

**Весь существующий набор тестов файла должен продолжать проходить
без изменений** — это регрессионная проверка на то, что подстрочное
совпадение не сломало точные синонимы (единственный способ, которым
существующие тесты могли сломаться).

`frontend/src/pages/NewSitePage.test.tsx` — новый/дополненный кейс:
рендер `/sites/new` без загруженного графика показывает обновлённый
текст подсказки с перечислением распознаваемых названий колонок.

## Критерии готовности

- [ ] `_find_header` совпадает по подстроке; весь существующий набор
      `test_schedule_parser.py` проходит без изменений.
- [ ] Новый тест на длинную официальную формулировку колонки — проходит.
- [ ] Новый тест на двухстрочную XLSX-шапку (как в реальном файле) —
      проходит.
- [ ] Текст ошибки при отсутствии колонки перечисляет распознаваемые
      названия, сохраняя префикс `"Не найдена колонка"`.
- [ ] Подсказка в `NewSitePage`/`FileDrop` перечисляет распознаваемые
      названия колонок; есть тест, проверяющий текст подсказки.
- [ ] `uv run pytest -q` (backend) — весь набор зелёный.
- [ ] `pnpm test` (frontend) — весь набор зелёный.
- [ ] Ручная проверка (опционально, если стенд поднят): реальный файл
      графика СМР с двухстрочной шапкой из этой сессии успешно
      импортируется без ручной правки.
