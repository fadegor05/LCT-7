## 1. TASK

- **[F] Название:** «Автоматизированный сервис поиска нарушений на строительных площадках Москвы». Заказчик — Департамент градостроительной политики Москвы.
- **[F] Ключевой фокус:** «доказать ценность автоматического сопоставления снимков со строительных площадок с графиком строительных работ, продемонстрировать понятный механизм выявления отклонений».
- **[F] Обязательные функции:**
  1. Обнаружение и классификация техники на снимках.
  2. Сопоставление с графиком **на основе методики, сформированной участниками** — набор правил «этап работ → необходимая техника».
  3. Визуализация (минимальный интерфейс).
  4. Выявление отклонений: отсутствие необходимой по плану техники; появление техники, не соответствующей этапу; «другие отклонения по методике».
- **[F] Эталонный пример алерта:** этап «Устройство котлована», виден экскаватор, нет самосвалов → «возможное снижение темпа работ» + затронутая зона + подтверждающие снимки.

## 3. METRIC

- **[F] Числовой метрики и лидерборда нет.** Оценка экспертная:
  - 8.1 Подход: оригинальность, архитектура, **логика сопоставления**, **механизм объяснения предупреждений**, обоснованность технологий.
  - 8.2 Техника: качество кода; **модульность и расширяемость** (новые типы снимков, техники, планов); **скорость обработки и задержка алертов**.
  - 8.3 Соответствие задаче: **качество распознавания и устойчивость на разнообразных примерах** (экспертная оценка), **явная и проверяемая связь техника↔этап**, качество алертов, **UI для быстрой оценки статуса площадки**.
  - 8.4 Полнота требований раздела 2, качество документации.
  - 8.5 Питч (финал): убедительность, ответы на вопросы, наглядность демо.
- **[F] Тестовой выборки нет.** Команда сама формирует валидационный набор «на разнообразных изображениях, с учётом освещённости, сезонности, видов техники».
- **Следствие [H]:** mAP нужен как **доказательство устойчивости** (per-class, per-season, per-viewpoint), а не как цель. Главные рычаги баллов — объяснимость, проверяемость правил, устойчивость на показательных примерах, UI, документация, скорость на CPU.

## 9. Что изменилось относительно pre-mortem (research/part_0_analysis.md)

| Гипотеза pre-mortem | Статус | Следствие |
|---|---|---|
| Данные — видео/CCTV с фиксированных камер | **опровергнута** | MOT, micro-motion, гомография фиксированной камеры, idle/working — нерелевантны для текущих данных. Только как «путь развития» в презентации |
| Будет календарный график с датами | **опровергнута (пока)** | Графики делаем сами; методика «этап → техника» — центральный артефакт |
| Есть числовая метрика | **опровергнута** | Оптимизация на экспертную оценку: объяснимость, устойчивость, UI, скорость |
| Временная информация есть | **частично подтверждена** | Даты на снимках + серии по площадкам = разреженный помесячный time-lapse с плавающим ракурсом. Даёт отклонения «нет прогресса между датами» и «состав техники не менялся N месяцев» |
| Циклический приор — главный риск | **понижен** | Стадию по снимку при известном графике не выводим — проверяем совместимость наблюдения с плановой стадией. Риск остаётся, если добавить классификатор стадии по сцене |
| Неинъективность техника→этап | **подтверждена визуально** | Экскаватор есть почти везде; буровая установка — наоборот, почти однозначный сигнал |
| Observability / воздержание от вывода | **усилена** | Аэро-кадры с мелкими объектами и частичный обзор площадки → «не вижу» ≠ «нет». Готовый дифференциатор + рекомендации по камерам |
| Рекомендации по установке камер | **новое требование ТЗ** | Выводить из собственного анализа ошибок (размер объектов, ракурс, окклюзии) — дёшево и доказательно |

4. Засчитываются ли классы вне списка ТЗ (буровые установки, башенные краны) как плюс при оценке?
5. «Прототип, доступный жюри» — нужен публичный хостинг, или достаточно Docker + инструкции?
6. Есть ли ограничения на лицензии внешних данных (NC, GPL) при открытом репозитории?
7. Документация `.doc` — подойдёт ли `.docx`?

## 12. Retarget research (вместо общего обзора литературы)

HIGH:
1. Правила «этап → техника»: ГЭСН/ФЕР (разделы «Машины и механизмы»), ППР и технологические карты на котлован, сваи, шпунт, монолит → источник для обоснования методики с цитатами.

MEDIUM:
