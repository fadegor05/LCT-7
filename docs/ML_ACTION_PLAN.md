### 1.3 Контракт данных с командой — 45 мин ⭐
- `docs/CONTRACTS.md`:
  1. **Detection result:** image_id, **source_type {cctv, photo}**, camera_id / site_id, timestamp, model_name + **model_license** + version, время обработки; детекции — class_fine, class_coarse, conf, bbox (явно: пиксели или нормализованные, xyxy); флаги наблюдаемости снимка.
  2. **Rule:** код этапа по справочнику; **варианты технологии — альтернативные комплекты техники (ИЛИ)**, например плита = (автобетононасос ИЛИ башенный кран) И автобетоносмеситель [part_I вывод 3]; для каждой машины — тип обязательности: `normative` (есть в «Машинах и механизмах» ГЭСН) / `logical` (самосвал, автобетоносмеситель — в ГЭСН не входят, поэтому **не могут быть единственным доказательством этапа**) / `auxiliary`; поле `checkable_by_equipment: bool` (для вырубки, гидроизоляции, фасада, озеленения — `false` → система отвечает «не проверяемо по технике», а не «нарушение»); минимальные количества; **source: номер расценки ГЭСН / ТТК** [part_I]; уверенность правила; версия. «Неожиданная техника» — всегда помечать как гипотезу: в нормах таких указаний нет.
  3. **Alert:** тип, этап, площадка, окно дат, ожидалось / наблюдалось, уровень уверенности, id снимков-доказательств, текст объяснения, id сработавших правил.

## ДЕНЬ 2 (16–17.09) — zero-shot, разметка, аудит Kaggle

### 2.1 E1: zero-shot open-vocab — 2–3 ч
- **Гипотеза:** open-vocab детектор даёт приемлемый recall на наших классах и годится для псевдоразметки.
- **Кандидаты** [part_K shortlist E1]:
  - **A** — MM-Grounding-DINO-T (Apache; 1–2 с/кадр на CPU);
  - **B** — YOLOE-26 с текстовыми **и визуальными** промптами (AGPL; реальное время) — главный кандидат на «буровая vs гусеничный кран»: промптом служит рамка-пример;
  - **C** — SAM 3 на GPU (Colab/Kaggle) офлайн + Qwen3-VL для проверки спорных кропов (веса по запросу, лицензия Meta).
- **Запуск:** на 100 фото **и** на 100 кадрах Kaggle из разных камер.
- **Выход:** таблица «класс × домен × {хорошо / частично / провал}» + время на кадр.
- **Контекст из research:** zero-shot на сложных доменах часто проваливается; дообученный компактный детектор его обходит [part_K вывод 3]. Роль E1 — псевдоразметка и нижняя планка, не финальная модель.
- **Ловушки:** вшитая дата детектируется как объект; взрыв числа промптов.

### 2.2 E3 (часть 1): разметка 100 фото с псевдоразметкой — 4–5 ч
- **Инструмент** [part_K блок 3]: **X-AnyLabeling v4** — есть exe под Windows, встроены Grounding DINO / YOLOE / SAM 3 / Florence-2, экспорт YOLO и COCO. Альтернатива — CVAT (Docker + WSL2). **Не Roboflow Free:** данные становятся публичными.
- Размечай по сериям площадок. Замерь время на снимок после первых 10.
- **Ловушка:** confirmation bias — пропущенные объекты ищи отдельным проходом.

### 2.3 Аудит Kaggle CC0 — 2 ч ⭐ HIGH-ROI
- **Проверить:**
  1. Пересекаются ли `camera_id` между родными `train` и `valid`: если да, родной valid бесполезен.
  2. Число кадров и объектов по камерам и классам; какие классы живут только на 1–2 камерах (тогда модель выучит фон, а не класс).
  3. Плотность кадров во времени по камерам — это вход для E6.
  4. Разметка — bbox или полигоны; 50 кадров глазами: пропуски, ошибки классов.
  5. Near-duplicates: сколько остаётся после прореживания «1 кадр на камеру за N минут» + phash.
- **Выход:** `manifest_cctv.parquet` + `DECISIONS.md`: сплит leave-camera-out, правило прореживания, классы для слияния.

## ДЕНЬ 3 (17–18.09) — измерения и gate G1

### 3.1 E3 (часть 2): завершить разметку + QA — 2–3 ч

### 3.2 Протокол валидации — 30 мин ⭐ MUST
| Домен | Валидация | Hold-out (не трогать до финала) |
|---|---|---|
| Фото (организаторы) | grouped K-fold по площадкам | 20–30 новых фото других площадок из открытых источников (проверить условия использования) |

- **Отчёт всегда содержит матрицу «обучение на домене X → тест на домене Y»** + срезы по сезону, ракурсу и размеру объекта.

### 3.3 E4: размеры объектов — 1 ч
- Распределение площади bbox по классам, доменам и ракурсам; доля < 32² и < 16² px.
- **Решение про SAHI:** по данным part_K он даёт +5–7 AP на мелких объектах, но стоит ~5× по времени. Включать только там, где мелких объектов много (аэро-кадры).
- Цифры пойдут в рекомендации по установке камер.

### 3.4 E5: насколько техника определяет этап — 1.5 ч ⭐ HIGH-ROI
- По ручной разметке 100 фото — таблица совместной встречаемости «класс × этап».
- Для каждого снимка — сколько этапов совместимы с набором техники по черновым правилам [part_I]. Какие классы несут больше всего информации об этапе.
- **Ожидание из ГЭСН (проверить на данных):** буровая установка + автобетононасос + автобетоносмеситель + фронтальный погрузчик — почти однозначный признак свай CFA [I03]; экскаватор + бульдозер — разработка грунта [I01], но и засыпка, и планировка [I13, I15].
- **По part_I (вывод 5):** самые специфичные классы — **асфальтоукладчик, буровая установка, грейферная установка СВГ, вибропогружатель**; экскаватор, краны и самосвалы встречаются на многих этапах. Отсюда постановка для методики: не «угадать этап по технике», а **проверить совместимость наблюдённой техники с этапами, активными по графику на дату снимка**, с учётом пар (экскаватор + самосвал). E5 должен измерить, сколько снимков остаются неоднозначными даже при такой постановке.

### 3.5 E6: пригодны ли CCTV-ряды Kaggle для временной логики — 1 ч
- **Гипотеза:** на части камер кадры достаточно плотны и длинны, чтобы показать отклонения во времени («техника исчезла на N дней», «состав сменился»).
- **Проверить:** по манифесту из 2.3 — длительность ряда, пропуски, число кадров в день на камеру; на 1–2 лучших камерах — ряд «число объектов по классам во времени» по **разметке** (не детектору).
- **Решение:** делать ли демо временных отклонений на CCTV в дополнение к сериям фото по датам.

    - ≥ 25 px/m на дальней границе зоны — обнаружение (IEC 62676-4 DORI);
    - ≥ 62,5 px/m — различение типа техники;

  - **Проверить своими данными:** на E4 и срезах ошибок B3 подтвердить порог в пикселях на наших данных, а не только по литературе. Это превращает слайд из пересказа норм в вывод из экспериментов.
