# Задача: `tools/site_state.py` — состояние площадки

Второе звено пайплайна: детекции по кадрам → состояние площадки на дату.
Дальше это состояние сравнивается с графиком, поэтому решения, принятые здесь,
определяют, что вообще можно будет проверить.

## Что на входе

| Файл | Что берём |
|---|---|
| `data/processed/detections_1280.json` | детекции: `image`, `detections[]` с `class_ours`, `conf`, `bbox` |
| `data/reference/sites.csv` | `image` → `site_id`, `date` |

## Что на выходе

Одна запись на пару «площадка + дата»:

```json
{
  "site_id": "p08",
  "date": "2024-04-24",
  "images": ["Screenshot_33.png", "Screenshot_34.png", "..."],
  "n_images": 9,
  "equipment": {"drilling_rig": 4, "crawler_crane": 2, "excavator_crawler": 1},
  "conf_threshold": 0.25,
  "observability": {"aerial": 2, "ground": 7}
}
```

Формат зафиксируйте в `docs/CONTRACTS.md` — им будет пользоваться следующий скрипт.

---

## Главная ловушка: не складывайте кадры

Одна площадка в одну дату снята с нескольких ракурсов. На пяти кадрах один и тот
же экскаватор попадёт пять раз. Если просто сложить детекции, получится
«5 экскаваторов» там, где он один, и все последующие сравнения с нормами
поедут.

**Вопрос, который вам нужно решить:** как из нескольких кадров получить одно
число на класс?

Три варианта, у каждого своя цена:

1. **Максимум по кадрам.** `drilling_rig` = максимум среди кадров этой даты.
   Просто и устойчиво к дублям между кадрами. Занижает, когда площадка большая
   и техника не помещается в один кадр.
2. **Медиана по кадрам.** Устойчивее к выбросу на одном неудачном кадре, но
   так же занижает и хуже объяснима пользователю.
3. **Сумма с последующим сопоставлением объектов между кадрами.** Точнее всего
   и заметно сложнее: нужно понять, что экскаватор с кадра 33 и с кадра 34 —
   один и тот же. Для фоторепортажей с разных точек это отдельная задача.

Выберите вариант, запишите обоснование в `DECISIONS.md`. Для правил вида
«нужен хотя бы один буровой станок» разница между вариантами почти не важна, а
для «нужно 2–3 самосвала» — важна очень.

## Алгоритм

```
разобрать аргументы
загрузить детекции и sites.csv
сгруппировать кадры по (site_id, date)

для каждой группы:
    для каждого кадра:
        отфильтровать детекции по порогу
        (по желанию) схлопнуть дубли внутри кадра по IoU
        посчитать классы в этом кадре
    свести кадры в одно число на класс выбранным способом
    собрать запись

записать JSON
напечатать сводку
```

## Что решить по дороге

**1. Порог уверенности.** Из прогона 1.3: `excavator_crawler` и `pile_driver`
живут около 0.2, `drilling_rig` и `dump_truck` — на уровне шума 0.09–0.11.
Единый порог 0.25 отрежет шум вместе с частью редких классов.

Подумайте: не сделать ли порог **свой для каждого класса**, задаваемый в конфиге?
Тогда его можно будет настроить, когда появится разметка, не трогая код.

**2. Дубли внутри кадра.** В прогоне на 1280 их 31%, вложенных рамок 12%.
Если не схлопывать, счётчики завышены втрое. Схлопывание — это то же подавление
перекрытий, но по вашему правилу: у вас есть и IoU, и «доля площади внутри
большей рамки».

**3. Кадры без даты или площадки.** У 41 кадра нет `site_id`, у 48 нет даты.
Решите: пропускать молча, складывать в группу `unassigned` или падать с ошибкой.
Молча пропускать — худший вариант: потом не поймёте, почему площадок меньше
ожидаемого.

**4. Наблюдаемость.** Сколько кадров в группе и какого типа. Это понадобится
на уровне алертов: вывод «техники нет» по одному аэрокадру и по семи наземным
снимкам имеет разный вес. Достаточно счётчиков.

## Проверка

```bash
.venv\Scripts\python.exe tools\site_state.py --detections data\processed\detections_1280.json --sites data\reference\sites.csv --out data\processed\site_state.json
```

Что должно получиться:

1. Записей примерно 15–20 (11 площадок, у некоторых несколько дат).
2. Для `p08` на `2024-04-24` — буровые установки должны быть в списке: на этих
   кадрах их видно глазами.
3. Ни одного класса с неправдоподобным числом вроде 40 самосвалов.

Третий пункт — главный тест. Если увидите такое число, значит дубли не схлопнуты
или кадры сложены.
