# API

Бэкенд отдаёт 58 эндпоинтов под префиксом `/api` (настройка `API_PREFIX`). Интерактивная документация OpenAPI открывается на `/api/docs`, схема на `/api/openapi.json` и описывает все эндпоинты и схемы. Ниже подробно описаны аутентификация, камеры, объединение этапов и уведомления. Остальные перечислены в разделе [«Остальные эндпоинты»](#остальные-эндпоинты).

## Аутентификация

Все эндпоинты кроме `/auth/login`, `/auth/register`, `/health`, `/ready` и `/version` требуют заголовка `Authorization: Bearer <jwt>`. Без авторизации вернёт `401 Требуется авторизация`.

### POST /api/auth/login

Вход по логину и паролю.

**Тело запроса:**
```json
{
  "login": "string",
  "password": "string"
}
```

**Ответ 200:**
```json
{
  "access_token": "eyJhbGc...",
  "token_type": "bearer",
  "user": {
    "id": "uuid",
    "full_name": "string",
    "login": "string",
    "created_at": "datetime"
  }
}
```

**Ошибки:**
- `401 Неверный логин или пароль` — логин не найден или пароль неверен. Одно и то же сообщение для обеих случаев.
- `429 rate_limited` (код ошибки) — слишком много попыток входа по логину. Лимит задаётся `AUTH__LOGIN_RATE_LIMIT_PER_MIN` (по умолчанию 10 попыток в минуту). Подождите и повторите.

JWT подписан алгоритмом HS256, содержит claims `sub` (user_id), `iat` (время создания), `exp` (время истечения). Время жизни токена — `AUTH__TOKEN_TTL_MINUTES` (по умолчанию 720 минут). Токены не обновляются, новый токен нужно получить повторным входом.

### POST /api/auth/register

Саморегистрация: создаёт пользователя и сразу выдаёт токен, как вход.

**Тело запроса:**
```json
{
  "login": "string",
  "password": "string",
  "full_name": "string"
}
```

`login` от 3 до 64 символов, приводится к нижнему регистру, пробелы по краям срезаются. `password` от 8 до 256 символов. `full_name` необязателен, по умолчанию равен логину.

**Ответ 201:** тот же, что у `/auth/login` (`access_token`, `token_type`, `user`).

**Ошибки:**
- `409 Логин уже занят` (код `login_taken`).
- `422` — логин или пароль не прошли проверку длины.
- `429 rate_limited` — слишком много регистраций. Лимит `AUTH__REGISTER_RATE_LIMIT_PER_MIN` (по умолчанию 5 в минуту) считается по адресу клиента. За Traefik это адрес прокси, поэтому лимит общий для всех.

Все зарегистрированные пользователи равны: ролей нет, каждый видит только свои стройки.

## Камеры стройки

Камера принадлежит стройке. Пути ниже начинаются с `/api/sites/{site_id}`. Доступ к стройке проверяется как у остальных эндпоинтов: чужая стройка даёт `404`.

Ссылка на стрим: `rtsp://`, `rtsps://`, `http://` или `https://`, не длиннее 500 символов. Пароль из ссылки в ответах заменён на `***`, например `rtsp://***@host`. Если такую маскированную ссылку прислать обратно в `PATCH`, сервис возьмёт пароль из сохранённой ссылки. Сама ссылка с паролем хранится в базе.

Рабочая зона `zone` — многоугольник из 3–100 вершин. Каждая вершина `[x, y]`, координаты от 0 до 1 (доли кадра). Зона не может быть почти вырожденной: площадь не меньше 1e-4. Без зоны поле равно `null`.

Название зоны `zone_name` — необязательная строка до 100 символов («Въезд», «Склад»). Пустая строка или из одних пробелов сохраняется как `null`. Название попадает в текст отклонения «Вне зоны» и в строку «Зона «…»: вне зоны» ленты наблюдений; без названия тексты прежние.

Объект камеры (`CameraRead`): `id`, `name`, `stream_url`, `capture_every_s`, `last_capture_at`, `last_capture_attempt_at`, `last_capture_error`, `capture_failures`, `zone`, `zone_name`, `frames_count` (сколько фотографий привязано к камере), `created_at`.

### GET /api/sites/{site_id}/cameras

Камеры стройки в порядке создания.

**Ответ 200:** массив `CameraRead`.

### POST /api/sites/{site_id}/cameras

**Тело запроса:**
```json
{
  "name": "Кран у забора",
  "stream_url": "rtsp://user:password@192.0.2.10:554/stream1",
  "capture_every_s": 300,
  "zone": [[0.1, 0.4], [0.9, 0.4], [0.9, 0.95], [0.1, 0.95]]
}
```

`name` от 1 до 100 символов. `capture_every_s` от 60 до 86400 секунд. Если есть ссылка и интервал не задан, берётся 300 секунд. Без ссылки интервал не хранится.

**Ответ 201:** `CameraRead`.

**Ошибки:** `422` — пустое или некорректное название, ссылка не того протокола или слишком длинная, зона не прошла проверку, интервал вне диапазона.

### PATCH /api/sites/{site_id}/cameras/{camera_id}

Частичная правка: поля, которых нет в теле, не меняются. `"zone": null` убирает зону, `"zone_name": null` — название зоны. `"stream_url": null` (или пустая строка) убирает ссылку и интервал. При смене ссылки счётчик сбоев и текст последней ошибки сбрасываются.

**Ответ 200:** `CameraRead`.

**Ошибки:** `404 Камера не найдена` — камеры нет или она другой стройки. `422` — те же причины, что при создании; `"name": null` тоже `422`.

### DELETE /api/sites/{site_id}/cameras/{camera_id}

**Ответ 204** без тела. Фотографии камеры остаются, у них `camera_id` становится пустым. Выводы по стройке при этом не пересчитываются.

### POST /api/sites/{site_id}/cameras/{camera_id}/capture

«Снять кадр сейчас». Кадр снимается со стрима синхронно и попадает в ленту стройки обычной фотографией с источником даты `channel` (дата момента снятия). Тело не нужно.

**Ответ 201:** `PhotoRead` созданной фотографии.

**Ошибки:**
- `404 Камера не найдена`.
- `422 У камеры нет ссылки на стрим`.
- `422` с причиной, если кадр не получен. Примеры текстов: `Камера отказала в соединении`, `Камера не пустила: проверьте логин и пароль в ссылке`, `По ссылке нет видео`, `Камера не ответила за 15 с`, `Адрес в частной сети не разрешён настройками сервиса (STREAM__ALLOWED_NETWORKS)`, `Это адрес самого сервиса, а не камеры`, `На сервере нет ffmpeg: снимки со стрима недоступны`. Такая неудача считается сбоем камеры: растёт `capture_failures`, текст пишется в `last_capture_error`.
- `409 Снимок с этой камеры уже идёт` — второй одновременный снимок с той же ссылки не запускается.
- `409 Ссылку камеры изменили во время снимка — снимите кадр ещё раз`.

Работает, даже если фоновые снимки выключены (`STREAM__ENABLED=false`). Подробнее в [configuration.md](configuration.md#снимки-со-стрима-камер).

### POST /api/sites/{site_id}/cameras/{camera_id}/video

Загрузка отрывка записи с камеры. Файл режется на кадры с заданным шагом, кадры попадают в ленту этой камеры и обрабатываются фоновой очередью как обычные снимки. Время кадра — начало записи плюс смещение.

**Тело:** `multipart/form-data`.
- `file` — видеофайл.
- `recorded_at` — начало записи, ISO-дата и время (`2026-10-20T09:30:00`). Без пояса считается местным временем стройки (`STREAM__TIMEZONE`), с поясом переводится в него.
- `step_s` — шаг кадров в секундах, от `VIDEO__MIN_STEP_S` до `VIDEO__MAX_STEP_S`, по умолчанию `VIDEO__DEFAULT_STEP_S`. Первый кадр берётся с нулевой секунды.

**Ответ 201:** тот же отчёт, что у загрузки фото (`items`, `uploaded`, `failed`) плюс `duration_s` (длительность видео) и `step_s`.

**Ошибки:**
- `404 Камера не найдена`.
- `413` — файл больше `VIDEO__MAX_MB`.
- `422` — шаг вне допустимого диапазона; `Файл не похож на видео`; `В отрывке получится N кадров, максимум M. Увеличьте шаг до S с или больше`; `На сервере нет ffmpeg: загрузка видео недоступна`.

### Фотография с камеры при загрузке

`POST /api/sites/{site_id}/photos` принимает необязательное поле формы `camera_id`. Камера должна принадлежать той же стройке, иначе `404 Камера не найдена`. Фотография получает `camera_id` и участвует в проверке рабочей зоны. Интерфейс загрузки это поле не передаёт, поэтому пока оно используется только через API.

## Объединение этапов графика

### POST /api/sites/{site_id}/schedule/stages/merge

Объединяет соседние этапы графика в первый из них.

**Тело запроса:**
```json
{
  "stage_ids": ["3f1c9a0b-...", "7d2e44a1-..."]
}
```

Не меньше двух идентификаторов. Порядок в списке не важен: сервис сортирует этапы по их месту в графике.

**Что происходит.** Остаётся первый этап: его название и идентификатор. Плановое окно становится объединением дат всех этапов. Если хотя бы один этап правили вручную, даты помечаются как ручные. Правило методики первого этапа получает наборы техники остальных; одинаковые наборы не дублируются. Этап становится проверяемым, если проверяемым был любой из объединяемых. Остальные этапы и их правила удаляются, порядок перенумеровывается, статусы пересчитываются.

**Ответ 200:** `ScheduleReport` с этапами после объединения.

**Ошибки:**
- `404` — стройка не найдена или чужая, график не загружен (`График не загружен`), какой-то этап не найден.
- `422` — меньше двух идентификаторов, либо все одинаковые (`Выберите хотя бы два разных этапа`), либо этапы не соседние (`Объединять можно только соседние этапы`).


## Уведомления

Лента всегда своя: адресат берётся из токена, чужие уведомления недоступны.

### GET /api/notifications

Страница ленты, новые сверху. Параметры строки запроса: `limit` (1–200, по умолчанию 50) и `offset` (от 0).

**Ответ 200:**
```json
{
  "items": [
    {
      "id": "b8d5d32c-...",
      "type": "system",
      "title": "Отклонение",
      "body": "Нет экскаватора",
      "link": "/sites",
      "read_at": null,
      "created_at": "2026-10-18T11:50:53.133508Z"
    }
  ],
  "unread_count": 1
}
```

`unread_count` считает всю ленту, а не выданную страницу. `read_at` пусто у непрочитанного.

**Ошибки:** `422` — `limit` вне диапазона 1–200.

### POST /api/notifications/read

Помечает прочитанным всё непрочитанное текущего пользователя одним запросом. Это делает шторка при открытии.

**Ответ 200:** `{"marked": 2}` — сколько записей тронули. Повторный вызов вернёт `{"marked": 0}`.

### POST /api/notifications/digest

Сводка по объектам текущего пользователя прямо сейчас: кнопка «Отправить сводку сейчас» в шторке уведомлений. Текст собирается из последнего пересчёта: по каждому объекту итог (отставание интервалом или «в графике»/«данных недостаточно»), число критичных отклонений и предупреждений, отстающие этапы с днями. Отклонённые инженером гипотезы в счёт не идут. Уведомление типа `digest` попадает в ленту и во все включённые каналы; ссылка ведёт на `/sites`. Тело запроса не нужно.

**Ответ 201:** созданное уведомление.

**Ошибки:** `409` — у пользователя нет ни одного объекта.

Та же сводка уходит автоматически раз в неделю каждому владельцу объектов (см. `NOTIFY__DIGEST__*`).

### POST /api/notifications/test

Служебное создание произвольного уведомления себе — для демо и ручной проверки.

**Тело запроса** (все поля необязательны):
```json
{
  "title": "Отклонение",
  "body": "Нет экскаватора",
  "type": "system",
  "link": "/sites"
}
```

**Ответ 201:** созданное уведомление.

## Каналы доставки

### GET /api/users/me/channels

Привязки текущего пользователя. Пустой список, если ничего не привязано.

**Ответ 200:**
```json
[
  {
    "channel": "telegram",
    "address_masked": "…6789",
    "enabled": true,
    "linked_at": "2026-10-18T11:50:53.133508Z"
  }
]
```

Полный адрес наружу не отдаётся никогда: у телеграма видны последние четыре символа, у почты первая буква и домен (`i***@example.com`).

### POST /api/users/me/channels/{channel}/link

Выдаёт одноразовую ссылку привязки. `channel`: `telegram` или `email`.

**Ответ 200:**
```json
{
  "url": "https://t.me/<бот>?start=<токен>",
  "expires_at": "2026-10-18T12:05:53.133508Z"
}
```

Пользователь открывает ссылку, телеграм шлёт боту `/start <токен>`, и фоновый поллер привязывает `chat_id`. Токен живёт 15 минут и гасится первым использованием.

**Ошибки:** `409 Канал «телеграм» не настроен на сервере` — не заданы `NOTIFY__TELEGRAM__TOKEN` и `NOTIFY__TELEGRAM__BOT_USERNAME`. Нерабочая ссылка не выдаётся.

**Почта (`channel=email`).** Тело: `{"address": "ivan@example.com"}`. Адрес не привязывается сразу: на него уходит письмо со ссылкой подтверждения, а `url` в ответе пуст.

```json
{ "url": null, "expires_at": "2026-10-18T12:05:53.133508Z" }
```

**Ошибки почты:** `409 Канал «почта» не настроен на сервере`, `422` — адрес не указан или не похож на e-mail, `502` — письмо не ушло (токен при этом не сохраняется).

### GET /api/notifications/email/confirm?token=…

Публичный роут, без авторизации: ссылку из письма открывают в браузере. Гасит токен, привязывает адрес из токена и отвечает `302` на `<NOTIFY__PUBLIC_URL>/profile?email=confirmed` либо `…?email=invalid`, если токен неизвестен, уже использован или просрочен. Токен одноразовый, живёт 15 минут.

### PATCH /api/users/me/channels/{channel}

Тело: `{"enabled": false}`. Выключает доставку, не снимая привязку.

**Ответ 200:** привязка. **Ошибки:** `404 Канал не привязан`.

### DELETE /api/users/me/channels/{channel}

Снимает привязку. Историю уведомлений не трогает.

**Ответ 204.** **Ошибки:** `404 Канал не привязан`.

## Остальные эндпоинты

Подробности по схемам запросов и ответов смотрите в OpenAPI. Все они, кроме служебных, требуют `Authorization: Bearer <jwt>` и работают только со стройками текущего пользователя.

| Метод и путь | Что делает |
|---|---|
| `GET /health`, `GET /ready`, `GET /version` | Живость, готовность (база и детектор, `503` при недоступной базе), версия сервиса и модели. Без авторизации |
| `GET /users/me`, `PATCH /users/me` | Профиль текущего пользователя, смена имени |
| `POST /sites`, `GET /sites`, `GET /sites/{site_id}`, `PATCH /sites/{site_id}`, `DELETE /sites/{site_id}` | Стройки: название, адрес, тип объекта, рабочие дни |
| `POST /sites/{site_id}/schedule/import` | Загрузка графика (CSV или Excel), режим разбора `auto`, `llm` или `builtin` |
| `GET /sites/{site_id}/schedule` | График, этапы и ошибки разбора |
| `PATCH /sites/{site_id}/schedule/stages/{stage_id}` | Ручная правка плановых дат этапа |
| `GET /sites/{site_id}/methodology`, `PATCH .../methodology/rules/{rule_id}` | Методика стройки, включение и отключение проверки этапа |
| `POST .../methodology/rules/{rule_id}/sets`, `PUT`, `DELETE .../methodology/sets/{set_id}` | Комплекты техники этапа |
| `POST .../methodology/apply-defaults` | Подставить базовые комплекты в пустые правила |
| `GET /equipment-types` | Справочник типов техники |
| `POST /sites/{site_id}/photos` | Загрузка пачки снимков (`multipart`, необязательное поле `camera_id`), ответ сразу после сохранения, обработка в очереди |
| `GET .../photos/progress` | Ход обработки очереди загрузок |
| `GET .../photos`, `GET .../photos/{photo_id}` | Лента снимков и один снимок |
| `PATCH .../photos/{photo_id}/date`, `POST .../photos/time-batch` | Ручной ввод даты и пакетный ввод времени кадров |
| `GET .../photos/{photo_id}/image`, `GET .../photos/{photo_id}/annotated` | Оригинал и снимок с рамками |
| `POST .../photos/detect`, `POST .../photos/{photo_id}/detect` | Повторное распознавание: всех необработанных снимков или одного |
| `GET /sites/{site_id}/observations`, `GET .../observations/{observed_on}` | Наблюдения по дням |
| `GET /sites/{site_id}/assessment/stages`, `GET .../summary` | Статусы этапов и итог по объекту |
| `GET .../assessment/deviations`, `GET .../deviations/{deviation_id}` | Список отклонений и карточка отклонения |
| `PUT .../assessment/deviations/{deviation_id}/decision` | Решение инженера по гипотезе: подтвердить, отклонить или снять (`decision: null`) |
| `POST .../cameras/preview` | Пробный кадр по ссылке на стрим без сохранения камеры |
| `POST /sites/{site_id}/assistant/ask`, `GET /assistant/status` | Вопрос ассистенту по отчёту и признак, подключена ли модель |
