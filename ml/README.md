# ml — распознавание техники и сопоставление с графиком

Часть решения ЛЦТ-7: по снимкам строительной площадки определяет, какая техника
на них есть, и сравнивает наблюдения с календарным планом — отстаёт этап или
идёт по графику.

## Быстрый запуск

```bash
python tools/fetch_weights.py                 # веса (нужен HF_TOKEN в ml/.env)
docker build -t lct7-ml . && docker run -d -p 8000:8000 \
    -v "$PWD/weights:/weights:ro" lct7-ml     # сервис детекции
curl -X POST -F "file=@frame.png" http://localhost:8000/detect
```

Без докера: `python -m service.detector <кадр>` покажет детекции в консоли.

## Что где лежит

```
service/       сервис детекции: detector.py (обёртка) и app.py (HTTP)
tools/         инструменты: детекция, обучение, оценка, разметка, разбор планов
configs/       правила «этап → техника», сопоставление названий, промпты
data/
  raw/         исходные снимки (в git не хранятся)
  reference/   разметка, привязка кадров к площадкам, графики, эталоны
  processed/   выходные JSON: детекции, состояния, отчёты
  interim/     рабочие наборы для обучения (в git не хранятся)
docs/          документация, см. таблицу выше
weights/       веса (в git не хранятся, качаются скриптом)
```

## Основные инструменты

| файл | зачем |
|---|---|
| `tools/detect_finetuned.py` | прогон модели по папке снимков |
| `tools/site_state.py` | свод детекций по паре «площадка + дата» |
| `tools/match_schedule.py` | статусы этапов и алерты по графику |
| `tools/parse_schedule.py` | календарный план заказчика (Excel или PDF) в наш формат |
| `tools/eval_groups.py` | оценка качества на размеченных площадках |
| `tools/scene_stage.py` | замер: определяется ли стадия по виду сцены (E21) |
| `tools/eval_external.py` | оценка на внешнем наборе теми же группами классов |
| `tools/train_ours.py` | обучение на смеси наборов |
| `tools/fetch_weights.py` | загрузка весов из приватного репозитория |

Полный список с пояснениями — в docstring каждого файла.

## Качество

На площадках p03 и p08, которых модель не видела (28 кадров, 215 ручных рамок):

| | |
|---|---|
| mAP50 по группам классов | 0.445 |
| точность / полнота | 0.70 / 0.66 |
| статусы этапов, совпавшие с эталоном | 18 из 20 |

Классы, по которым у нас мало рамок, измерены отдельно на **отложенном сплите
MOCS** (1373 кадра): грузовики AP50 0.715, бурение 0.533 (E22). Это другой домен,
поэтому цифры стоят отдельно от основной метрики.

Путь: 0.121 у модели без обучения → 0.445 сейчас. Что сработало и что отвергнуто
замерами — в сводке `EXPERIMENTS.md`.

## Окружение

Python 3.12, `.venv` в корне проекта. Torch ставится **не с PyPI**: обычная
установка даёт сборку `+cpu`, и GPU молча не используется. Подробности и
проверенные версии — в `requirements.txt`, там же про Smart App Control на
Windows.
