# Первый код: zero-shot детектор на 100 снимках (эксперимент E1)

Задача поставлена так, чтобы за один заход получить настоящий результат и
разобраться в инструментах. Код пишешь ты — здесь идея, алгоритм и контрольные
точки, по которым видно, что шаг сделан правильно.

**Результат на выходе:** `data/processed/detections_zeroshot.json` — детекции по
всем 100 снимкам в схеме контракта, контакт-листы вырезов по классам и честная
таблица «что модель видит, а что нет».

**Зачем именно это первое.** Разметка 100 снимков вручную — 5–7 часов. С
псевдоразметкой — 2–3 часа, потому что правишь готовые рамки, а не рисуешь с
нуля. Плюс это ответ на вопрос G1: нужен ли вообще fine-tune или zero-shot уже
достаточен. Плюс тот же скрипт потом станет модулем восприятия в пайплайне.

---

## Этап 0. Окружение (15 мин)

Виртуальное окружение в проекте, `torch` под CUDA 12.x с официального индекса
PyTorch (обычный `pip install torch` ставит CPU-сборку — это частая ловушка).

**Контрольная точка:** `torch.cuda.is_available()` → `True`,
`torch.cuda.get_device_name(0)` → упоминание 4060.

Сразу допиши зависимости в `requirements.txt` рядом с уже зафиксированными
четырьмя — версии закрепляй точно, как там сделано.

---

## Этап 1. Выбор модели

Два кандидата из `research/part_K_models_tooling.md`. **Начни с A** — он
запускается за 15 минут, и этого достаточно, чтобы понять, стоит ли возиться с B.

**A. YOLOE (пакет `ultralytics`)**
- Плюс: быстрый, ставится одной строкой, принимает текстовые промпты, а также
  **визуальные** — рамку-пример вместо слова. Для «буровая против гусеничного
  крана» это главная надежда: словами их различить трудно, примером — реально.
- Минус: лицензия AGPL-3.0 (см. решение D-001).

**B. MM-Grounding-DINO**
- Плюс: лицензия Apache, качество по тексту выше.
- Минус: 1–2 с на кадр на CPU, стек `mmdetection` на Windows ставится тяжело.

**Что делать:** взять модель размера `s` или `m`, не самую большую. Цель этапа —
не максимум качества, а понимание, где модель ломается.

Точные имена классов и сигнатуры смотри в документации пакета: API меняется от
версии к версии, и лучше один раз свериться, чем ловить ошибку.

## Этап 2. Один снимок (30 мин)

Прогнать **один** кадр и посмотреть результат глазами, прежде чем писать цикл.

Возьми не первый попавшийся, а показательный: `Screenshot_26` — буровые
установки крупно, или `Screenshot_50` — котлован, экскаваторы, башенный кран.

**Промпты.** Английские, по 2–3 синонима на класс. Начни с семи:

```
excavator, tower crane, crawler crane, drilling rig, dump truck,
wheel loader, concrete mixer truck
```

**Контрольная точка:** есть хотя бы одна рамка, ты понимаешь структуру ответа —
где координаты, где класс, где уверенность, и в каком формате координаты
(`xyxy` в пикселях или нормализованные — это важно для схемы контракта).

**Вопрос себе:** что модель назвала буровой установкой? Проверь глазами каждую
такую рамку. Скорее всего, часть окажется гусеничными кранами — это и есть
главная гипотеза, которую проверяет E1.

## Этап 3. Все 100 снимков → JSON (45 мин)

Теперь скрипт `tools/detect_zeroshot.py`. Стиль возьми из соседних инструментов:
docstring про «почему», `argparse`, `pathlib`, датакласс результата.

**Алгоритм:**

```
разобрать аргументы: папка со снимками, выходной файл, порог, промпты
загрузить модель один раз (не в цикле!)
для каждого снимка:
    замерить время инференса
    получить детекции
    отфильтровать по порогу
    привести к схеме контракта
    накопить в список
записать json
напечатать сводку: снимков, детекций, среднее время, счётчик по классам
```

**Схема одной записи** — из `docs/CONTRACTS.md`, минимум:

```
image, source_type, model_name, model_license, inference_ms,
detections: [ {class_raw, class_ours, conf, bbox_xyxy_px} ]
```

`class_raw` — что ответила модель, `class_ours` — наш класс из
`LABELING_SPEC.md`. **Держи оба:** когда поменяешь промпты, сможешь сравнить
запуски, не перезапуская всё.

**Три ловушки:**
1. **Штамп даты** в углу может детектироваться как объект. Посмотри, есть ли
   рамки в правом нижнем углу.
2. **Порог уверенности.** Один общий порог для всех классов — плохо: у редких
   классов уверенность систематически ниже. Сохраняй все детекции от примерно
   0.05 и фильтруй на анализе, а не на инференсе. Переделывать прогон дорого.
3. **Модель в цикле.** Загрузка весов на каждом кадре — и 100 снимков будут
   идти полчаса вместо двух минут.

**Контрольная точка:** JSON на 100 записей, среднее время на кадр известно.
Запиши его — на CPU оно понадобится для критерия «скорость работы» (ТЗ, 8.2).

## Этап 4. Посмотреть глазами (30 мин)

Числа сейчас обманут: эталона нет, сравнивать не с чем. Смотри картинки.

**4.1. Вырезы по классам.** Вырежи все рамки одного класса, сложи в папку и
собери контакт-лист уже готовым инструментом:

```bash
python tools/make_contact_sheets.py data/interim/crops/drilling_rig -o data/interim/review/drilling_rig --cols 6 --rows 6 --tile 220 --aspect 1.0
```

Один лист по `drilling_rig` ответит на главный вопрос быстрее любой метрики:
сколько там настоящих буровых, а сколько кранов.

**4.2. Рамки на кадрах.** Отрисуй детекции поверх снимков (`PIL.ImageDraw` уже
есть) и пройди глазами десяток кадров. Ищи **пропуски** — модель их не покажет,
их видно только тебе.

**Контрольная точка:** по каждому классу ты можешь сказать «хорошо / частично /
провал» и назвать характерную ошибку.

## Этап 5. Честная таблица (20 мин)

Запиши в `EXPERIMENTS.md`: гипотеза, что сделал, результат, решение.

| класс | найдено | из них верно (глазами) | вердикт | типичная ошибка |
|---|---|---|---|---|

**Решение, которое нужно принять:**
- классы, где вердикт «хорошо» → псевдоразмечаем автоматически, ты только
  проверяешь;
- «частично» → псевдоразметка как черновик, правишь руками;
- «провал» → размечаешь с нуля.

Это прямо экономит часы на этапе E3.

## Чего не делать

- **Не гнаться за качеством zero-shot.** По `part_K` дообученный компактный
  детектор существенно обходит zero-shot на узких доменах. Роль E1 —
  псевдоразметка и нижняя планка, а не финальная модель.
- **Не считать mAP.** Не с чем сравнивать: эталона пока нет.
- **Не перебирать промпты бесконечно.** Два-три захода, дальше отдача падает.
