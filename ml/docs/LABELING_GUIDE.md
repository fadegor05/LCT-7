# Инструкция разметчику

Рабочая инструкция, а не теория. Полные критерии классов — в
`docs/LABELING_SPEC.md`, здесь порядок действий и то, на чём мы уже ошибались.

**Наглядник:** `data/reference/guide/classes.png` — как выглядит каждый класс на
наших снимках, вырезано из уже проверенной разметки.
`data/reference/guide/activity.png` — то же по состояниям working / idle.

---

## 1. Порядок работы

Размечаем **партиями по площадкам**, а не подряд по номерам кадров: кадры одного
объекта похожи, и глаз не перестраивается между разными стройками.

**Шаг 1 — черновик от детектора.** Готовые рамки, чтобы не рисовать с нуля.
Партии p05, p07, p09, p11 уже собраны гибридом (YOLOE + дообученная модель
Захара) и лежат в `data/interim/label/<площадка>`. Для новой партии:

```powershell
..\.venv\Scripts\python.exe tools\merge_detections.py --config configs\merge_draft.json --out data\processed\detections_merged_draft.json
..\.venv\Scripts\python.exe tools\to_labeling.py data\processed\detections_merged_draft.json -o data\interim\label\<группа> --only <имена кадров>
```

Черновик собирается с **низкими** порогами (`configs/merge_draft.json`): лишнюю
рамку удалить быстрее, чем нарисовать пропущенную. Для боевого прогона пороги
другие, выше — см. `configs/merge.json`.

**Шаг 2 — правка в X-AnyLabeling.** `File → Open Dir` → папка `data\interim\label\<группа>`.
Рамки подтянутся сами. `Ctrl+S` сохраняет кадр; удобно включить `Auto Save`.

**Шаг 3 — проверка.**

```powershell
..\.venv\Scripts\python.exe tools\check_labels.py data\interim\label\<группа>
```

Должно вывести «ошибок нет». После этого JSON переносятся в
`data/reference/labels/<группа>` — это делает ведущий, картинки в git не идут.

## 2. Что делать с каждой рамкой

**Класс** — из словаря в `LABELING_SPEC.md` §3. Не уверены в точном типе —
ставьте coarse: `drilling_like`, `crane_like`, `excavator_like`, `truck_like`.
Честная крупная метка лучше шумной точной: модель учится на противоречиях.

**Рамка** охватывает машину **вместе с рабочим оборудованием**: мачтой, стрелой,
ковшом, прицепом. У буровой в транспортном положении рамка будет вытянутой
горизонтально — это нормально.

**Атрибут** пишется в поле описания рамки:

```
activity=working
activity=idle;offsite=true
```

- `activity` — `working`, `idle` или `unknown`. Критерии по типам техники — в
  `LABELING_SPEC.md` §7a (таблица по видам машин), наглядно — в `activity.png`.
- `offsite=true` — техника **соседней** стройки: за забором, через дорогу, башенные
  краны на горизонте. Ставится только когда это очевидно (`LABELING_SPEC.md` §7b).

---

## 3. Почему offsite размечается, а не пропускается

Соблазн — не трогать чужие краны. Так делать нельзя.

Объект нашего класса, оставленный без рамки, для модели означает «вот такое — не
кран». Она учится подавлять ровно то, что должна находить, и recall падает на
всём наборе.

Поэтому: **рамка ставится всегда**, а принадлежность отмечается атрибутом.
Обучение берёт все рамки, подсчёт техники на площадке — только свои.

## 4. Ошибки, которые мы уже совершили

**Две трети объектов детектор не находит.** В первой партии черновик дал 27 рамок,
после разметки стало 75. Не полагайтесь на черновик: пройдите кадр глазами
целиком, особенно задний план и края.

**Опечатки в классах.** Были `truck_unkniwn` и `acivity=unknown`. Файл читается,
обучение идёт, а класс с одним примером тихо живёт до момента, когда
переразмечать поздно. Поэтому `check_labels.py` запускается после каждой партии.

**Атрибут в поле класса.** Один раз строка `activity=idle` оказалась в поле метки
вместо класса. Проверка это ловит.

**Вложенные дубли.** Детектор ставит две рамки на одну машину — большую на всю
установку и малую на мачту. Лишнюю нужно удалить: подавление перекрытий их не
снимает, у вложенных рамок низкое IoU по построению.

**Машина в транспортном положении.** Буровая с опущенной мачтой не похожа на себя
же в работе, и детектор её пропускает. Такие примеры особенно ценны: без них
модель выучит «буровая = высокая вертикаль». Активность у них почти всегда `idle`.

Из первых двух партий (21 кадр, 146 рамок):

|---|---|---|
| `drilling_rig` | 43 | основной класс площадок p03 и p08 |
| `excavator_crawler` | 36 | встречается почти на каждом кадре |
| `tower_crane` | 16 | значительная часть — `offsite` |

| `truck_crane` | 7 | |
| `pile_driver` | **0** | настоящих копров в наших данных пока нет |

Отсутствие копров — важный факт: детектор без обучения массово метит буровые как
копры, и из-за этого в отчёте появлялся несуществующий этап шпунтового ограждения.
Если встретите настоящий копёр или вибропогружатель — это ценный кадр, отметьте
его отдельно.

## 6. Сколько размечать

Ориентир — **партия из 10–15 кадров одной площадки за заход**. Дальше падает
внимание, а ошибки разметки дороже пропущенных объектов: они учат модель
неправильному.

После каждой партии — `check_labels.py` и короткий взгляд на обновлённый
`classes.png`: объект, попавший не в свой класс, бросается в глаза рядом с
однородными соседями.
