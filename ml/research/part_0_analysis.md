## 0.1 Переходы пайплайна

| Переход | In → Out | Главная проблема | Подходы | Главный риск |
|---|---|---|---|---|
| A. Camera → Perception | кадр → `{class, bbox, score, t, cam}` | fine-grained различение техники на малом угловом размере | fine-tune детектора + tiling; «machine»-детектор + классификатор кропов; open-vocab как baseline/псевдометки | дисбаланс: стадии зависят от редких классов |
| B. Detections → Temporal | детекции → `presence/count/position(t)` | режим данных [U]; при time-lapse MOT неприменим | frame-агрегация; SORT-семейство при видео; зональные треклеты | архитектура, несущая на tracking, ломается на снимках |
| C. Temporal → Site state | ряды → `S_t` (counts, zones, idle/working) | presence ≠ activity | micro-motion кропов; геометрия позы; контекстные прокси (самосвал рядом, циклы) | нет GT активности → ручная разметка 200–300 объектов |
| D. Site state → Stage | `S_t` → `P(W)` multi-label | техника→работа не инъективно | правила/скоринг сигнатур; GBDT; HMM/CRF с порядком работ | циклический приор |
| E. Stage → Schedule | `P(W)` + план → conformity | разрыв гранулярности (минуты vs недели), параллельные работы | weighted similarity; байесовское обновление; DTW/state-space → сдвиг в днях | синтетический график [H] |
| F. Matching → Deviation | conformity(t) → `{type, task, evidence, conf}` | асимметрия: отсутствие ≠ доказанное отсутствие | пороги+гистерезис; change-point; кумулятивные профили | base rate → поток ложных алертов |
| G. Deviation → Alert | отклонение → карточка | нельзя утверждать причинность | декомпозиция скора; шаблоны observation/inference; ранжирование по критическому пути | «что делать менеджеру?» |

## 0.2 Неочевидные bottleneck'и

1. **Циклический приор.** План как приор для стадии + сравнение с тем же планом → отклонения подавлены. Лекарство: «слепой» путь вывода стадии (только наблюдения) для детекции отклонений, планово-информированный — только для UI/сглаживания.
2. **Неинъективность equipment→work.** Дискриминирует место + порядок + фаза объекта. Ablation: stage по (classes+counts) vs (+zone).
3. **Нет калибровки камеры → зоны неизмеримы.** Гомография image→генплан; автодетект сдвига камеры (ORB-гомография фона).
4. **Временной domain shift внутри одной камеры** (объект растёт). Валидация — строго по времени вперёд.
5. **Цензурированность FOV.** «Ушла» ≡ «вне кадра». Ввести observability и нормировать выводы.
6. **Multi-label + ненаблюдаемые работы.** Делить задачи графика на observable / partial / unobservable.
7. **Confidence не переживает агрегацию.** Калибровать на уровне решения или использовать честные ординальные уровни.
8. **Стоящая техника** неделями «подтверждает» работы → фильтр долговременной неподвижности.

## 0.3 Differentiators против «YOLO + dashboard»

1. Observability-aware вывод с воздержанием при низкой видимости.
2. Presence / activity / utilization раздельно (коэффициент использования техники).
3. Двухпутевая архитектура без циклического приора — показанная явно.
4. Привязка к генплану + автовосстановление зон при сдвиге камеры.
5. Алерт как объект: какая компонента сигнатуры не сошлась, evidence-кадры, тренд, сдвиг срока, обратная связь.
